# Physical AI 실습 스터디

LeRobot 기반 로봇팔과 Jetson을 이용해 **직접 조종 → 데이터 수집 → 모방학습 → 배포 → 언어 지시**를 경험하는 8주 실습 과정입니다. ROS 2, ViT, VLM을 같은 로봇 프로젝트에 단계적으로 연결합니다.

최종 프로젝트는 **“책상 위 블록을 트레이로 옮기는 동작을 학습하고, 자연어 지시로 실행하기”**입니다. 물체 하나, 고정 카메라, 제한된 시작 위치에서 출발해 데이터와 평가 결과를 바탕으로 개선합니다.

## 참여 대상과 운영 방식

- **선수 지식:** Python 기초, 터미널과 Git의 기본 사용. ROS와 로봇 제어는 입문 수준을 가정합니다.
- **기간:** 8주, 주 1회 3시간 모임 + 자율 실습 2~3시간. 모델 학습의 대기 시간은 별도입니다.
- **모임 구성:** 핵심 개념 30분 → 실습 120분 → 실행 영상·실패 사례 공유 30분.
- **팀 운영:** 장비 조작, 코드·모델 실행, 실험 기록 역할을 나누고 매주 교대합니다.
- **매주 산출물:** 실행 가능한 코드·설정, 실험 증거, 활동보고서.
- **핵심 목표:** 하나의 동작을 학습하고, 실패 조건의 데이터를 추가해 실제 성공률을 개선합니다.

## 장비와 실행 환경

현재 장비의 정확한 모델은 미확정입니다. 아래 커리큘럼은 **SO-101 같은 LeRobot 지원 로봇팔과 Jetson Orin Nano**를 우선 가정합니다. LeRobot은 특정 로봇 제품명이 아니라 로봇 학습·제어 프레임워크입니다.

| 구성 | 용도 | 준비 사항 |
| --- | --- | --- |
| 로봇팔 + 조종 장치 | 시연 수집과 실제 동작 | 예: SO-101 follower arm + leader arm. 모델별 전원·통신 부품 확인 |
| 고정 카메라 1대 이상 | 관측 영상 수집 | 촬영 위치·해상도·프레임률을 기록하고 고정 |
| Jetson | 로봇·카메라 연결과 배포 실험 | 정확한 보드 모델, 메모리, JetPack 버전 확인 |
| GPU PC 또는 GPU 서버 | ACT 학습, 초기 추론, VLM 실행 | 사용할 모델로 메모리와 의존성 사전 검증 |
| 블록·트레이·고정 작업대 | 공통 실습 과제 | 로봇 고정, 작업 영역과 시작 위치 표시 |
| 전원·케이블·저장 장치 | 안정적인 실습 운영 | 장비별 규격 확인, 영상·체크포인트 저장 공간 확보 |

### Jetson 모델에 따른 구성

| 보드 | 이 과정에서의 운영안 |
| --- | --- |
| **Jetson Orin Nano** | 학습은 GPU PC에서 수행하고, 로봇 연결과 정책 추론은 Orin에서 검증합니다. 자원이 부족하면 PC 추론과 비교하는 구성으로 진행합니다. |
| **기존 Jetson Nano** | ROS 2·LeRobot·AI 실행은 PC 중심으로 구성하고, Nano는 호환성을 확인한 카메라·장치 입출력을 담당합니다. 6주차에는 PC 추론과 Nano 사이의 통신 지연을 측정합니다. |

기존 Nano가 사용하는 JetPack 4는 지원이 종료된 계열입니다. 구매·설치 전에 보드 모델을 확인하고, 운영진이 실제 장비에서 전체 연결을 검증해야 합니다. [NVIDIA 지원 현황](https://developer.nvidia.com/embedded/faq)

### 시작 전 준비

- [ ] 보드·로봇팔·조종 장치·카메라 모델을 확정한다.
- [ ] JetPack, Python, PyTorch, LeRobot, ROS 2의 조합을 실제 장비에서 검증하고 버전을 고정한다.
- [ ] ROS 2와 LeRobot의 실행 환경을 분리하고, 프로세스 사이의 연결 방식을 준비한다.
- [ ] 모터 명령을 쓰는 프로세스는 하나로 정하고, ROS 2 연결 코드의 뼈대를 제공한다.
- [ ] 장비 조립·전원·통신·카메라 연결을 사전 확인한다. 1주차에는 보정과 구동에 집중한다.
- [ ] GPU 학습 환경과 데이터 저장 위치를 준비한다.
- [ ] 관절 범위·속도 제한·정지 방법을 확인한다.

이 저장소의 문서는 커리큘럼과 기록 양식입니다. 실행 코드와 검증된 설치 이미지는 별도로 준비해야 합니다. 최신 설치 요구사항은 [LeRobot 설치 문서](https://huggingface.co/docs/lerobot/installation)를 확인합니다.

## 각 기술의 역할과 실습 범위

| 기술 | 프로젝트에서 맡는 역할 | 기본 과정의 범위 |
| --- | --- | --- |
| **ROS 2** | 영상·상태 전달, 작업 시작·중지·상태 관리 | 토픽과 실행 흐름에 집중. 로봇 연결 코드의 뼈대는 운영진 제공 |
| **ViT** | 고정 작업 영역의 시각적 상태 분류 | 사전학습 특징 추출과 작은 분류기 학습. 물체의 3차원 위치 추정은 확장 과제 |
| **LeRobot + ACT** | 시연 기록, 정책 학습, 관측에 따른 행동 생성 | 단일 집기 과제의 모방학습과 개선 |
| **Jetson** | 장비 입출력과 배포 성능 실험 | 로컬 추론 가능 여부·지연·메모리를 실측하고 PC 구성과 비교 |
| **VLM** | 이미지와 언어 지시를 해석해 작업 실행 여부 판단 | PC 실행을 기본으로 하고, 허용된 작업 ID와 실행 조건을 검증한 뒤 호출 |

3주차 ViT는 작업 영역을 인식하는 별도 모듈로 사용합니다. ACT 기본 시각 백본은 ResNet-18이므로, ACT 내부에 ViT를 넣는 작업은 심화 범위입니다. [ACT 구조](https://huggingface.co/docs/lerobot/act)

7주차의 연결 흐름은 **이미지·지시 → VLM 판단 → 허용 작업·장면 조건 확인 → ROS 2 실행 요청 → ACT 정책 → 로봇 동작**입니다. VLM 판단은 작업 단위로 수행하고, 관절 명령은 로봇 실행 프로세스가 관리합니다. 3주차 분류기는 실행 전 작업 영역 상태를 확인하는 데 연결할 수 있습니다.

강화학습, SLAM·자율주행, 복잡한 경로 계획, 대형 모델 사전학습은 기본 과정에서 다루지 않습니다. 여유 있는 팀은 같은 데이터로 **SmolVLA를 미세조정하고 ACT와 비교**할 수 있습니다. [SmolVLA 안내](https://huggingface.co/docs/lerobot/smolvla)

## 공통 평가 원칙

1. **성공 기준을 먼저 정합니다.** 예: 정해진 제한 시간 안에 사람이 개입하지 않고 블록을 지정 트레이에 놓으면 성공. 시간 제한과 시작·종료 조건은 실험 전에 고정합니다.
2. **학습과 평가를 분리합니다.** 연속 프레임을 무작위로 섞기보다 에피소드·촬영 세션 단위로 분리합니다. 익숙한 조건과 새로운 위치·조명 조건의 결과도 따로 기록합니다.
3. **성공률에는 분모를 씁니다.** `성공 횟수 / 전체 평가 시도 횟수 × 100`. 중단·사람 개입·시간 초과는 별도 기록하며, 결과를 보고 임의로 제외하지 않습니다.
4. **비교 조건을 맞춥니다.** 카메라, 해상도, 시작 위치, 평가 횟수 등을 기록하고 정책 v1/v2에 같은 조건을 적용합니다.
5. **지연 구간을 명시합니다.** 모델 추론 시간, 통신 시간, 관측부터 명령까지의 시간은 구분합니다. 측정 횟수와 평균·p95를 함께 기록합니다.
6. **실패도 증거로 남깁니다.** 학습 손실뿐 아니라 실제 성공률, 실패 유형, 로그·영상을 남깁니다. 미측정 값은 0으로 채우지 않고 `미측정`으로 표시합니다.

## 활동보고서 작성 방법

주차별 템플릿은 `reports/templates/`에 있습니다. 템플릿을 팀 또는 개인 폴더로 복사해서 작성합니다.

```text
README.md
reports/
├── templates/
│   ├── week-01.md
│   ├── week-02.md
│   ├── week-03.md
│   ├── week-04.md
│   ├── week-05.md
│   ├── week-06.md
│   ├── week-07.md
│   └── week-08.md
└── team-a/              # 작성자가 생성하는 예시 폴더
    └── week-01.md       # 복사 후 작성하는 보고서
```

```bash
mkdir -p reports/team-a
cp reports/templates/week-01.md reports/team-a/week-01.md
```

- `team-a`를 팀명 또는 이름으로 바꾸고 해당 주차 파일을 복사합니다.
- `미작성`을 실제 내용으로 채웁니다. 해당하지 않는 항목은 `해당 없음`, 수행하지 못한 항목은 이유와 후속 계획을 적습니다.
- 체크박스는 실제 완료한 항목만 표시합니다. 목표 수치와 실제 측정 결과를 구분합니다.
- 코드 커밋, 설정, 데이터셋 버전, 체크포인트, 영상·로그 위치를 연결합니다.
- 영상·데이터셋·모델처럼 큰 파일은 공용 저장소에 보관하고 보고서에 접근 가능한 링크를 남깁니다.
- 모임 종료 시 초안을 공유하고, 자율 실습 후 결과와 다음 주 계획을 갱신합니다.
